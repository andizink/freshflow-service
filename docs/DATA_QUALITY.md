# FreshFlow — Data Quality: Defect Catalog and Rule Mapping

This is the formal, traceable mapping from the defects measured in the four
challenge CSV files (D1–D10, described for a general audience in
[DATA_GUIDE.md](DATA_GUIDE.md)) to the deterministic normalization rules
(N1–N7) and quarantine rules (Q1–Q5). The rules are defined in
[PLAN.md](PLAN.md) §4.2–§4.3 and implemented in `app/ingest/normalize.py`
and `app/ingest/rules.py`.

Every count below is a **measured** value from profiling the real files
(PLAN.md §1.1 / §1.2, corroborated by the per-defect table in
`DATA_GUIDE.md` §2). None are invented or estimated ad hoc. Each row is
**measured at profiling; verified by the e2e suite against
`tests/e2e/expected_counts.json`**, which is generated by an independently
written profiling script (PLAN.md §6.1, §9), so the "expected" numbers are
derived twice rather than copied from the ingest implementation itself.

because they describe row-level conditions found during processing rather
than one named upstream data-quality pattern. D10 is one concrete, named

empty `name` or `category` cell hits the same rule.

| Rule | Condition | Outcome | Implementing function | Test module |

## 2. Rule ID quick index

- **Normalization (N1–N7):** N1 store_id, N2 item_number, N3 dates, N4
  category/tags, N5 free-text whitespace, N6 inventory quantity, N7
  exact-duplicate dedup.
- **Quarantine (Q1–Q5):** Q1 negative_quantity, Q2 unknown_item, Q3
  invalid_value/missing_field, Q4 conflicting_duplicate, Q5
  invalid_date_order.

Every rule ID above is cited in the docstring of the function that
implements it (`app/ingest/normalize.py`, `app/ingest/rules.py`), per the
project's documentation standard (PLAN.md §2.2). This file, the code and
the test suite are kept in agreement by a traceability meta-test
(`tests/unit/test_traceability.py`, PLAN.md §6.1). It asserts three things:
that every rule ID N1–N7/Q1–Q5 appears in at least one `app/ingest` module
docstring; that each is visible, by file name or docstring, in at least one
`tests/unit` module; and that each is cited by *exactly* the canonical set
of public functions that own it, via a pinned `RULE_OWNERS` table. Any
drift in rule ownership — a new public function claiming a rule, or an
owner dropping its citation — fails the build and has to be updated
deliberately.

---

## 3. Single source of truth

The rule definitions themselves (thresholds, exact wording of reason codes,
which fields each rule applies to) live in one place: `app/ingest/rules.py`
for quarantine and `app/ingest/normalize.py` for normalization, referenced
by both this document and the test suite. If this document and the code
ever disagree, the code and its rule-ID-cited docstrings win. A discrepancy
here is a documentation bug to fix, not a sign the implementation should
change to match stale prose.
